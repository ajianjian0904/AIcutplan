# 把「识图」派发给 WorkBuddy（DeepSeek 只管管理）

目标：**DeepSeek 不再逐张读图**，只负责「派任务 → 收 JSON → 仲裁分歧 → 落盘」；
读图判定交给 WorkBuddy（CodeBuddy ACP），用免费视觉模型 `hy4flash-free`。

实测日期：2026-11-17 · 工程 EP01 · 模型 `hy4flash-free`（0.00 credits）· 全程约 5 分钟。

---

## 一、通道

| 工具 | 用途 |
|---|---|
| `workbuddy_doctor` | 连通性自检（node / CLI / ACP / 模型数） |
| `workbuddy_models` | 列模型；挑 `supportsImages: true` 且 credits 低的 |
| `workbuddy_session_start` | 起会话：`cwd` + `prompt` + `modelId` + `permissionMode: plan` |
| `workbuddy_session_send` | 同一会话追加任务（多轮，省重复解释规则） |
| `workbuddy_session_report` / `_status` | 取结果 / 查状态 |

要点：
- `cwd` 必须是**目标工程目录**（它要按相对路径读图与 plan 文件）；
- `permissionMode: plan` 只读，不会改你的工程；
- 用 `session_send` 复用会话，规则只需讲一次。

## 二、协议（三段式）

### 第 1 段：讲清规则 + 一批样例

```
你是剪辑质检员。打开 `.qcframes/session/grid_00.jpg`（640×540，2 列×3 行，
格 1..6 左上→右下），逐格判断画面是否支持对应旁白：
格1=句0「…」 … 格6=句5「…」
match=1 支持 / match=0 明确不符；320px 缩略帧，钩子段可宽松。
只输出 JSON 数组：[{"i":0,"match":1,"why":"≤20字"},…] 不要改文件。
```

### 第 2 段：批量（让它自己读 plan 文件，省 token）

```
.qcframes/session/grid_01.jpg ↔ plan_01.json … grid_04.jpg ↔ plan_04.json
每张 2×3，格序 = plan 数组顺序，输出 24 条 JSON。
```

> 关键技巧：**只给图片路径 + plan 文件路径**，让 WorkBuddy 自己读句子文本，
> 不用把 54 句全文贴进 prompt。

### 第 3 段：probe 复核（必做）

单帧在空镜/转场上假阳性率实测 **13%**（7/54）。把它的 0 分句子交给引擎生成复核图：

```bash
python -m aicutplan qc --project <pj> --probe    # → .qcframes/session/probe_miss.jpg
```

再把 `probe_miss.jpg`（每行一句 × 3 帧）发给 WorkBuddy，要求「3 帧里有 1 帧支持就改 1」。

## 三、DeepSeek 的职责（管理者）

1. **验收通道**：doctor/models 通过才派活；
2. **写判定**：把返回的 JSON 落成 `verdict_XX.json`（它不写文件）；
3. **仲裁分歧**：以「台词 > 画面」定案，例：
   - 句4「几个老头密谋」：它看画面判 0，但该窗台词是「追放ってのは いいことずくめだぜ」→ 台词支持，判 1；
   - 句11「直接被扔出门」：画面只到「怒视」，扔出门在下一句 → 真预叙，保留 0；
4. **归档**：`runs snapshot` 记录本轮质检来源。

## 六、镜头描述也能派，但要控批次与选型

让 WorkBuddy 重做镜头 1–6 的描述（读 `.shotdesc/shot_00XX{F,M,L}.jpg`），对照既有
`shots_desc.json`（会话内产出）。**两个模型盲测同一批**：

| 镜 | 既有（会话） | `hy4flash-free` | `deepseek-v4.1-flash` |
|---|---|---|---|
| 1 | 标题卡+制作名单 | 标题卡 ✅ | 标题板+制作名单 ✅ |
| 2 | 白发老人执烛台 | 戴帽大胡子**侧坐** ❌ | 红袍人**背身**站 + 烛台 ✅（漏“白发”） |
| 3 | 老人仰头张嘴 | 大胡子张嘴 ✅ | 老人张嘴露齿 ✅ |
| 4 | 两人影对坐密谈 | 一人仰头 ❌ | **两人剪影相对而坐** ✅ |
| 5 | 手伸杯→举杯 | 举杯相碰 ✅ | 白发老者举杯仰饮 ✅ |
| 6 | 光头胖男灌酒 | 大胡子侧脸 ❌ | **秃顶+绿领带** ✅ |

抽帧核对镜2：画面是「白发老人、暗红长袍、背身站立、手端酒杯」——
免费模型错在姿态与人，`v4.1-flash` 只漏了“白发”，明显更准。

- 6 镜 ≈ 55–75 秒；
- 20 镜同批试过一次：**5 分钟无进展**（免费模型被 30 张图拖住），只能取消；
- 成本：`v4.1-flash` x0.11 credits，一集几十镜也就 1 credit 量级。

**结论**：
1. 批次压到 **6–10 镜**；
2. **默认用 `deepseek-v4.1-flash`**（认人准），免费模型只适合质检宫格这类粗判定；
3. 只信 `desc` 的动作/场景与 `depth` 的情绪，人名与物件抽 1–2 镜核对；
4. **不要整表覆盖** `shots_desc.json`——补漏可以，替换要人工复核。

## 七、质检的模型交叉验证（同集 54 格）

同一集用两个模型各判一遍，比较「单帧原始判定」与「probe/仲裁后的最终结论」：

| | `hy4flash-free` | `deepseek-v4.1-flash` |
|---|---|---|
| 单帧判 0 | 7 句（2,4,11,17,20,27,47） | 4 句（11,17,20,27） |
| probe 后仍 0 | 1 句（11） | 未做 probe（3 句已知是 17/20/27 的抽样噪声） |
| 与最终结论一致 | 54/54（经 probe+仲裁） | 54/54（原始判定已对齐最终结论，除 3 例已知噪声） |

结论：**两个模型都能锁定唯一真失配（句11 预叙），差别只在误报多少。**
免费模型多误报在「钩子复用段」（句2/4/47——它不知道那是提前复用的原片），
`v4.1-flash` 多误报在空镜/转场（句17/20/27）。
**probe 是消噪的关键，不是可选项。**

## 八、注意

- `permissionMode: plan` 下它**不能写文件**，判定必须由我们落盘；
- 它可能把「钩子段」判严（画面是复用片段），规则里要提前说明；
- 每次 `session_send` 会累积会话上下文，长会话记得换新 session 控制成本。
