## 问题③：帧缓存换源片不失效（P0，先修）

**根因**：`story_parse.grab()` 只判 `out.exists() and size>800`；文件名 `s{段号}_{秒}.jpg`
不含任何输入版本。`shot_desc` 的 `shot_XXXX{F,M,L}.jpg`、`scene_desc` 的 `frame_%05d.jpg`
是同一类问题，只是这次没爆。

**修法**：用项目自己的规范（`cache.content_sig` + `sig_valid`），不要发明新机制。

`aicutplan/shared/story_parse.py`：

```python
from aicutplan import cache as CACHE
from aicutplan.io import dump_json, load_json

FRAMES_VER = "frames-v2"

def _frames_sig(proj_dir, seg: dict, n: int) -> str:
    """帧集合的指纹：源片内容 + 段区间 + 张数 + 缩放宽度 + 版本。"""
    src = source_video(proj_dir)
    return CACHE.content_sig(FRAMES_VER, CACHE.file_sig(src),
                             f"{seg['a']:.3f}", f"{seg['b']:.3f}", n, 320)

def seg_frames(proj_dir, seg: dict, n: int = 12) -> list:
    d = workdir(proj_dir) / "frames"
    d.mkdir(parents=True, exist_ok=True)
    a, b = seg["a"], seg["b"]
    span = max(1.0, b - a)
    n = max(4, min(16, int(n)))
    want = _frames_sig(proj_dir, seg, n)
    mf = d / f"_seg{seg['i']:02d}.json"          # 段级清单：sig + 帧清单
    cached = load_json(mf, default={}) or {}
    if cached.get("frames_sig") == want and cached.get("frames"):
        out, ok = [], True
        for t, name in cached["frames"]:
            p = d / name
            if not (p.exists() and p.stat().st_size > 800):   # 防半截文件
                ok = False
                break
            out.append((float(t), p))
        if ok:
            return out
    # 指纹不符 → 重抽；文件名带指纹前缀，新旧帧永不混用
    tag = want[:6]
    out = []
    for k in range(n):
        t = a + span * (k + 0.5) / n
        f = d / f"s{seg['i']:02d}_{int(t):05d}_{tag}.jpg"
        if grab(proj_dir, t, f):
            out.append((round(t, 1), f))
    dump_json(mf, {"frames_sig": want, "frames": [[t, p.name] for t, p in out]})
    return out
```

同样处理：`session/shot_desc.py::probe_frames`（把 `shot_XXXX{tag}.jpg` 改成
`shot_XXXX{tag}_{sig}.jpg`，sig 里含源片指纹 + 480/240 宽度）、
`session/scene_desc.py::probe_video`（`frame_%05d.jpg` → 目录加 `_sig` 子目录）。

**清理出口**：`aicutplan/clean.py` 加一个类别 `frames_stale`——扫 `frames/` 下
文件名指纹前缀与当前 manifest 不符的 jpg，走既有 `.trash` 可恢复流程。

**验证**（这是重点，别只看代码）：`tests/test_frames_cache.py`

```python
def test_seg_frames_invalidate_on_source_change(tmp_path):
    # 造 1 个假源片 + shots，抽一次 → 帧数 n
    # 改源片 mtime/内容 → 再抽 → 断言文件名前缀变化、manifest 更新
    # 再抽一次（不改源片）→ 断言不重抽（mtime 不变）
```

**成本**：40 行，半小时；风险低（纯缓存层）。

## 问题①：320px 读不清小字（P1 / P1.5 / P2 三步）

### P1.5 立刻止血：写稿规则（零代码）

在 `dsh-aicut/skill/SKILL.md` 的硬约束里加一条：

> 旁白里出现具体数值（等级/金额/次数）时，**必须能在该句覆盖窗口的台词里找到依据**；
> 画面里的浮字（+5154、残り3033）在 320px 抽帧下不可靠，不得作为唯一依据。
> 不确定就不写数字，用「数值直接翻了几十倍」这类模糊表述。

这一条能挡掉大部分「十三万点→一万三千点」类事故，因为它把责任从「读不清的图」转到
「可核对的台词」。

```python
def check_number_claims(items, wins, sent_win_idx, paras) -> list[str]:
    """旁白里的数值必须在该句覆盖窗口的台词里出现（ja 原文 + zh 译文）。"""
    out = []
    for it in items:
        vals = _num_values(it["text"])
        if not vals:
            continue
        lo, hi = sent_win_idx[str(it["i"])]
        t0, t1 = wins[lo]["src_start"], wins[hi]["src_end"]
        spoken = {v for p in paras if p["t1"] > t0 and p["t0"] < t1
                  for v in _num_values(p["text"])}
        missing = {v for v in vals if v not in spoken}
        if missing:
            out.append(f"句{it['i']} 数值 {sorted(missing)} 不在窗口台词里：{it['text'][:14]}")
    return out
```

同时写进 `narration.stats.number_claims`，`aicut_check` 打印出来。

### P2 真正读画面数字：本地 OCR（只跑含数字的句）

- 依赖：`pip install rapidocr-onnxruntime`（onnx，Windows 免编译，中文+日文可用）。
- 只对「旁白含数值」的句子跑，成本可控（EP01 54 句里可能只有 5–10 句）。
- 帧用 `media.extract_frame(video, t, dst, width=1280, quality=3)`——**不塞进 2×3 宫格**，
  宫格仍用 320 省 token，OCR 帧单独读。

```python
# aicutplan/chain/number_check.py  （新文件，L1）
from rapidocr_onnxruntime import RapidOCR
from aicutplan.media import extract_frame

_engine = None
def _ocr(path):
    global _engine
    if _engine is None:
        _engine = RapidOCR()
    res, _ = _engine(str(path))
    return [x[1] for x in (res or [])]

def numbers_in_frame(video, t, width=1280) -> set[float]:
    tmp = ...
    extract_frame(video, t, tmp, width=width, quality=3)
    return {v for line in _ocr(tmp) for v in _num_values(line)}
```

判定：`旁白数值 == 台词数值 ∪ 画面数值` 才算过；不一致时进 `qc_rewrite.json`，
提示「画面是 3033、旁白写 30 万」。

**成本**：半天（含装依赖与调 OCR 阈值）；收益是把已知限制里
「数字事实 OCR 交叉校验尚未实现」真正补上。

## 问题②：1 帧/15s 漏快动作（P3 / P4）

先认清影响面：漏帧只影响「事件里写了什么」，不影响成片画面（成片用原片）。
真正要保证的是「旁白描述 == 窗口画面」，那是 `qc_visual` 的职责。所以优先级低于 ①。

### P3 段级抽帧改「镜头感知」（推荐，零 token 成本）

不再按时间均匀撒 12 张，而是按段内**镜头边界**取代表帧：

- 段内镜头数 ≤ 12：一镜一帧（中点）；
- 镜头数 > 12：把镜头按时间切成 12 桶，每桶取 `evidence.score_shot` 最高的一镜中点
  （既覆盖时间，又优先信息量大的镜头）。

```python
def seg_frames(proj_dir, seg, n=12):
    shots = [s for s in load_json(json_dir/"shots_desc.json", default={}).get("rows") or []
             if s["b"] > seg["a"] and s["a"] < seg["b"]]
    if not shots:
        return _uniform_frames(proj_dir, seg, n)      # 没有镜头表就退回均匀
    if len(shots) <= n:
        marks = [(s["a"] + s["b"]) / 2 for s in shots]
    else:
        buckets = [shots[i::n] for i in range(n)]     # 或按时间均分桶
        marks = [ (max(b, key=score_shot)["a"] + max(b, key=score_shot)["b"]) / 2 for b in buckets ]
    ...
```

12 张图从「12 个时间点」变成「12 个不同画面」，快动作被拍到的概率显著上升，
**token 成本完全不变**。

### P4 两阶段补帧 + qc 多帧（要额外交互，按需做）

- 第一遍 12 帧让模型额外输出 `"zoom": [[a,b], …]`（最多 3 段，每段 ≤6s）；
- 第二遍对这些段按 **1 帧/秒**补抽（≤18 帧），只问「修正这段里的事件边界与动作」；
- 缓存第二遍结果（sig 含 zoom 区间）。
- 质检侧：`qc_visual --probe` 已对失配句抽 3 帧复核，可扩成「首/中/尾 + 1280 宽」，
  进一步压单帧假阳性。

**成本**：+1 次多模态调用/段（一集约 +3 次），实现半天。
