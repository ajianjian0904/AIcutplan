# 用 DSH 插件搭建自动剪辑工作流：可行性评估与搭建方案

评估对象：`E:\workbuddy\漫剪软件开发`（AICutplan 0.10.0）
评估环境：DSH Desktop / profile `desktop` / 已装 `dsh-ffmpeg 0.7.8`
产出：随本文附一个可直接安装的插件骨架 `dsh-aicut/`（12 个工具，3 个只读工具已实测通过）

---

## 一、结论

**可行，而且比重新写一遍更省事——但插件只该承担「确定性的机械动作」，创作判断必须留在会话里。**

三条判断：

1. **接口层完全够用**。AICutplan 已经把业务收进一个统一 CLI（`python -m aicutplan <cmd>`），
   12 个子命令覆盖体检、规划、旁白、质检、渲染、归档、清理。DSH 插件注册工具只需要
   `{name, description, parameters, output, execute}`，`execute` 里经 `ctx.subprocess` 或
   `node:child_process` 跑 argv 数组即可。这条路在你这个 profile 里**已经跑通过一次**：
   `dsh-ffmpeg 0.7.8` 就是这么接的，现在已注册 11 个 `ffmpeg_*` 工具。
2. **真正值钱的不是「把脚本变工具」，而是把规则固化成 skill**。你项目里所有事故都出在
   数据契约上（句子稿 `src` 与窗口不匹配、钩子段没专属文案、重切后没重写稿、拿文件存在当缓存）。
   这些规则写进 SKILL.md 后，模型每次动手前先加载，比在 12 个工具描述里重复一遍更省 token、
   也更不容易漏。
3. **不要整体重写成 JS**。Python 侧有 torch、faster-whisper、edge-tts、ffmpeg 封装和两个
   解释器口径，重写成本极高且没有必要。插件是**薄壳**：路径校验 + 选解释器 + 超时 +
   输出截断 + 失败指引，业务仍在 `aicutplan/`。

## 三、目标架构（三层，各管一件事）

```
┌────────────────────────────────────────────────────────────┐
│ 会话层（模型）                                              │
│  · 读 window_table.md 写句子稿                              │
│  · read_image 看宫格图，写 verdict_XX.json                  │
│  · 决定改哪句、要不要重规划                                 │
├────────────────────────────────────────────────────────────┤
│ dsh-aicut 插件（本次产出）                                  │
│  · 12 个工具：env/projects/status/check/subs/plan/           │
│    narrate/qc/render/batch/runs/clean                       │
│  · 路径校验、双解释器、超时、日志截断、退出码→下一步         │
│  · skill/SKILL.md：顺序、硬约束、失败排查                   │
├────────────────────────────────────────────────────────────┤
│ AICutplan 引擎（不动）                                      │
│  · python -m aicutplan + chain/ + batch/ + contracts/freshness│
│  · 本地校对台 python -m aicutplan serve :8765（仍独立进程） │
└────────────────────────────────────────────────────────────┘
```

**为什么这样切**：

- 插件做「调用」，引擎做「算」，模型做「判断」。任何一层越界都会重演历史事故：
  让插件猜句子内容 → 音画错位；让模型自己拼 ffmpeg → 绕过契约与门禁。
- 本地 web 校对台**不塞进插件**：它是人工审稿界面，另有 8765 端口和静态页，插件化收益低。
  需要时在会话里起后台任务即可（也可用 side bar browser 面板嵌）。
- 视频底层操作**不重复造**：已有 `dsh-ffmpeg` 的 11 个工具，本插件只调用 aicutplan 的业务命令。

|---|---|---|---|

| `aicut_status` | `guard --json` + `runs latest --json` + 产物元数据 | `project` | ✅ 1.1s 四阶段 |

| `aicut_plan` | `plan` | `project` | 未跑（会覆盖定型 cutplan） |
| `aicut_narrate` | `narrate --export` / `--sentences` | 二选一 | 未跑（写盘） |

## 五、六个必须做对的设计决策

1. **进程执行不用 shell 拼接**。全部 `argv` 数组：`[python, '-X', 'utf8', '-m', 'aicutplan', ...]`。
   优先用 `ctx.subprocess.spawn`（宿主管理进程范围、树级终止、tail 收集），缺失时退化
   `node:child_process`——这样同一份代码能在普通 Node 里冒烟测试。
2. **强制 UTF-8**。Windows 控制台代码页会让中文日志变 `�������`（我第一次直接跑 `check`
   就复现了）。子进程带 `PYTHONIOENCODING=utf-8 / PYTHONUTF8=1`，python 侧加 `-X utf8`。
3. **超时按工具分档**：体检 2 分钟、规划 15 分钟、渲染 45 分钟、批量 60 分钟。
   一刀切会让长任务被误杀，或让体检卡住 15 分钟。
4. **输出只回尾部**。渲染日志可以几 MB，工具结果只保留最后 40 行 + 退出码 + 下一步提示，
   完整日志留在工程目录。
5. **破坏性操作默认关闭**：`clean` 不带 `apply` 只列清单、`runs snapshot` 要显式动作、
   `subs` 默认只探测。`allow_stale` 只在描述里写明「仅调试」。
6. **退出码翻译成下一步**：2 参数/路径、4 门禁阻断、5 句子稿契约、6 前置完整性。
   这是把项目里最贵的经验（每次事故的根因）变成模型能直接执行的提示。

## 六、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 渲染是 10 分钟级同步等待 | 超时、会话卡住 | 工具预算 45/60 分钟；先用 `dry_run`；超大工程建议终端跑，插件只做归档与门禁 |
| 两个解释器装错 | 静默产出错结果 | 插件配置里分开 `python` / `ttsPython`，`aicut_env` 每次自检 |
| 模型自己编句子 | 音画错位（历史事故） | `narrate --sentences` 落盘前契约校验，退出码 5 直接拒；skill 里写明「禁止按窗口序号平均分配」 |
| 绕过门禁用旧素材 | 成片混入上一版画面 | `run` 默认走 `render_ready()`；`allow_stale` 明示仅调试 |
| 两条链写同一工程目录 | 覆盖已定型 cut-first 数据 | skill 明令：不要点 web 台 `/flow` 的运行按钮，审稿只用句级锚点 |
| 长日志撑爆上下文 | 后续步骤失焦 | 尾部截断 + 建议路径，不回灌全文 |
| 并发跑同一集 | 产物互相覆盖 | 同集同时只跑一个渲染（项目已有约定）；工具层不做锁，靠流程约束 |
| `ctx.subprocess` 语义差异 | 装进 DSH 才暴露 | 该分支未在真实宿主验证过；首次安装后先跑 `aicut_env`/`aicut_check` 两个只读工具确认 |

## 七、分阶段搭建路线

**P0（已完成）**：插件骨架 `dsh-aicut/`

```
dsh-aicut/
├── package.json            # dsh.bundle.patch + icon + locale 导出
├── cordis.patch.yml        # insert 一行 aicut，带默认 config
├── index.js                # apply(ctx, config)：注册 12 个工具
├── lib/config.js           # 默认值 + patch 合并 + 环境变量覆盖 + 超时分档
├── lib/run.js              # subprocess seam / child_process 双实现，有界 tail 收集
├── lib/cli.js              # 路径校验、argv、JSON 抽取、退出码提示、产物概览
├── lib/tools.js            # 12 个工具定义
├── locale/{zh,en}.json     # 插件面板标题/描述
├── docs/DETAIL.md          # 插件详情页
├── skill/SKILL.md          # 流水线操作手册（硬约束 + 排查表）
├── icon.svg
└── test/smoke.mjs          # 假 ctx 直连真实 aicutplan
```

**P1（下一步，5 分钟）**：安装并验证

1. DSH → Plugins → Add plugin → 选 `E:\workbuddy\漫剪软件开发\plugins\dsh-aicut`
   （或让我用 `plugin_manager install_bundle` 装）。
2. 新开一个会话，确认 12 个 `aicut_*` 工具在列表里。
3. 首次只跑只读三件套：`aicut_env` → `aicut_projects` → `aicut_status`。
4. 若 config 路径不同（换机器/换盘），改 profile `cordis.patch.yml` 里 `aicut` 行的
   `config` 整段，重启。

**P2（1 小时）**：把规则接进技能系统

- 把 `dsh-aicut/skill/` 放进技能根：仓库根 `.dsh/skills/aicut-workflow/SKILL.md`，
  或 profile 里给 `dsh-skill-filesystem` 配 `customSkillDirs`。
- 之后模型遇到「出一集/改旁白/质检」会先 `skill aicut-workflow` 加载手册，再动工具。

**P3（半天）**：把高频链路变「一键」

- 组合工具：`aicut_episode`（status→check→render→snapshot 串成一步，中途失败即停）。
- 后台任务化：长渲染改成起 job 返回 id + `job_output` 查进度，避免同步等待。
- 本地校对台：`aicut_studio` 起 `serve`（127.0.0.1:8765）并回 URL，或用 sidebar-browser 面板。

**P4（按需）**：面板与批量

- Client UI：流水线阶段灯 + 最新宫格图缩略（`ctx.slots.inject` + `--dsw-alias-*` token）。
- 批量：`aicut_batch` 接导演稿，多集排队，配 `runs verify` 做发布前校验。

## 九、还没做 / 未验证（别当成已完成）

- **插件尚未安装到 profile**：本次只产出骨架并本地验证；装与不装、装到哪个 profile 由你定。
- **`ctx.subprocess` 分支未在真实宿主跑过**：本地冒烟走的是 `node:child_process` 退化分支。
  首次安装后跑两个只读工具即可确认。
- **没有 Client UI 面板**：纯 Host 工具 + 文档，没有可视化阶段灯/宫格预览。
- **没有后台任务化**：长渲染仍是同步等待，P3 再改。
- **skill 尚未进入技能目录**：文件已备好，需手动放到技能根（P2）。

## 十、一句话建议

先把 **P1 装上去跑三个只读工具**——`aicut_env / aicut_projects / aicut_status` 就能覆盖你
80% 的「现在到哪一步、能不能渲染」的日常问题；确认 `ctx.subprocess` 分支正常后，再开
`render` 与 `qc` 这两条真正省时间的链路，最后才做面板。别一上来就追求「全自动一键出片」：
这条链的价值在**画面先定 + 逐句对图**，那部分恰恰需要模型在会话里看着画面做。
