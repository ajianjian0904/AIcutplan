## 二、四类插件各自负责什么（搞清楚这个就不会乱装）

| 类型 | 表现 | 这批里的例子 | 作用 |
|---|---|---|---|
| Host 工具插件 | 给模型加 `xxx_*` 工具，`execute` 里跑进程/算数据 | `dsh-ffmpeg`、`dsh-video-editor`、`dsh-aicut` | 让模型能动手 |
| Client UI 插件 | 加页面/面板/卡片，走槽位与主题 token | `dshmarket`、media-skills 的 Images 页 | 让人看得见、点得动 |
| Skill 插件 | 不加工具，只提供 `SKILL.md` 给 `skill` 工具按需加载 | `dsh-media-skills`（vision-review / media-tools） | 给模型规则与手法，不占常驻 token |
| MCP | profile 里挂 MCP server（如 qq-bridge 的 snowluma） | `mcp-snowluma` 等 | 接外部系统 |

**搭配原则**：能用 skill 解决的规则就不要塞进工具描述；能用现成插件干的事就不要自己写；
同一个「动作」只留一个来源，避免模型在两套口径之间摇摆。

## 三、一集成片里，各插件分别在哪一步

```
源片
 │
 ├─ ① 台词源 ────────────── aicut_subs（内嵌字幕优先）/ aicut_env 自检
 │                            ffmpeg_probe 核对片源（时长/轨道）
 ├─ ② 画面先定 ──────────── aicut_plan → cutplan.json
 ├─ ③ 粗剪 ──────────────── 工程目录 cut.py（仓库外，不由插件提供）
 │                            ffmpeg_frames / ffmpeg_storyboard 抽查画面
 ├─ ④ 写稿 ──────────────── aicut_narrate export → window_table.md → 模型写
 │                            需要看画面：read_image 或 vision-review
 ├─ ⑤ 落盘 ──────────────── aicut_narrate sentences（契约不过直接拒）
 ├─ ⑥ 出片 ──────────────── aicut_render（TTS + 适配 + 混音 + 合片）
 │                            ffmpeg_probe 复核成片时长/轨道
 ├─ ⑦ 质检 ──────────────── aicut_qc plan（出宫格图）
 │                            vision-review / read_image 逐格判定
 │                            aicut_qc merge → 改词 → aicut_render qc_apply
 ├─ ⑧ 包装（可选）───────── dsh-video-editor：片头 / 花字 / 动效卡
 │                            ffmpeg_concat 与正片拼接（需 reencode 统一参数）
 ├─ ⑨ 交付 ──────────────── ffmpeg_encode（B 站 1080p / 竖屏 1080x1920）
 │                            ffmpeg_subtitle（临时硬字幕预览）
 └─ ⑩ 归档 ──────────────── aicut_runs snapshot → latest.json（指纹校验）
                              aicut_clean 回收旧版
```

封面/缩略图：`ffmpeg_frames`（抽帧）＋ `media-tools`（生成）＋ video-editor（加字排版），
三条路任选，不要为了封面去动正片。

## 四、三条可选路线（按你实际需求选，不要混）

### 路线 A：纯 aicutplan（推荐主线）
`aicut_*` + 工程目录脚本。语义剪辑（选窗、旁白、音画对齐）全在这里，出片是 ffmpeg 直剪 + `-c:v copy`。
**适合**：一集 5–6 分钟的漫剪解说，要的是「讲明白剧情」。
**代价**：零 API、纯本地；旁白音色统一（edge-tts），没有花字动效。

### 路线 B：aicutplan 出正片 + ffmpeg 轻包装
aicutplan 出 `out/03-*.mp4` → `ffmpeg_encode` 转码 → `ffmpeg_concat` 接固定片头/片尾 → `ffmpeg_subtitle` 可选烧字幕。
**适合**：要统一片头、统一交付规格（B 站/竖屏）。
**代价**：拼接要 `reencode=true` 统一分辨率帧率；纯流拷贝会因参数不一致失败。

### 路线 C：video-editor 做「包装层」
`video_engine` 用 HTML 时间线渲染片头、花字、数据卡，输出 mp4 再拼到正片前。
**适合**：需要动效、排版、品牌感强的开场/转场。
**代价**：它是 Chromium 渲染，和 aicutplan 的 ffmpeg 直剪是**两条不同的出片引擎**；
`audio.generate` 走云 TTS/音乐是**计费**的，而 aicutplan 用本地 edge-tts 零 API。

## 五、三个必须知道的「别混用」

1. **别用 `ffmpeg_cut` 改 aicutplan 的窗口**。`ffmpeg_cut` 默认流拷贝、关键帧对齐；
   aicutplan 的 `cutplan.json` 要求 `t0 == windows[ws].new_start`（帧网格吸附后的精确值）。
   改窗口只能改 `cutplan.json` 的 `src_start/src_end` 再重跑 cut → narrate → mix → mux。
2. **别用 video-editor 的 TTS 配 aicutplan 的旁白**。旁白音色/语速是 `r5_tts + elastic_fit`
   按槽位算出来的，换一个引擎念，槽位预算和 `tts-result.json` 全部对不上。
3. **别为了「全自动」把写稿交给 LLM 自主写作**。`--sentences` 会话内写稿是主线（零 API），
   历史事故都是「按剧情顺序写 N 句、按窗口序号平均分配」造成的音画错位。

## 六、最小可用集合 vs 完整体

| 目标 | 需要启用 | 说明 |
|---|---|---|
| 只想「看状态、能出片」 | `dsh-aicut`（必须）+ 工程目录脚本 | 14 个工具够用；下层 ffmpeg 由 aicutplan 自己调 |
| 出片 + 素材核对 | 加 `dsh-ffmpeg` | probe/抽帧/总览图，排查「画面是不是这版」 |
| 出片 + 质检读图 | 加 `dsh-media-skills`（vision-review） | 也可直接用原生读图，批量 OCR 才需要它 |
| 要片头/花字/品牌感 | 加 `dsh-video-editor` | 按需开，别常开（工具 schema 很长，占 prompt） |
| 找新插件 | `dshmarket` | 用完即可留 |

**建议**：装饰类（whale/boot/skin）留着不影响；工具类按上表取舍。
`dsh-video-editor` 的 `video_engine` 单个 schema 就几千 token，不做包装时可以临时关掉，
省下来的上下文够你多读两张质检宫格图。

## 七、安装顺序（把 `dsh-aicut` 接进去）

1. 装 `dsh-aicut`（本地目录 `E:\workbuddy\漫剪软件开发\plugins\dsh-aicut`）。
2. 新会话跑 `aicut_env` → `aicut_projects` → `aicut_status <EP01>`，三个只读工具全绿再往下。
3. 把 `dsh-aicut/skill/SKILL.md` 放进技能根（仓库 `.dsh/skills/aicut-workflow/`，
   或给 `dsh-skill-filesystem` 配 `customSkillDirs`），让「顺序 + 硬约束」按需加载。
4. 之后再考虑 P3 的后台任务化与面板，别一上来就追「一键全自动」。
