# 漫剪解说流水线操作手册

这条链的核心是**时序翻转**：先按剧情理解定画面时间轴，再对着已定型的窗口写旁白。
同步靠生成顺序保证，不靠事后对齐。所以「先写 N 句再按窗口顺序平均分配」是**禁止**的
（钩子前置、块间取镜会跳时间线，会造成整条音画错位）。

## 1. 开工前

1. `aicut_env`：确认仓库根、两个解释器（规划/渲染 `D:\Python312`，TTS/ASR 为 workbuddy env）、ffmpeg。
2. `aicut_projects`：确认作品库路径，拿到「动漫/EPxx」工程目录。
3. `aicut_status --project <工程目录>`：读四个阶段是否 `fresh`，以及最新归档指针。
   - 有 `stale` → 先补跑它指出的上游阶段，别硬渲染。
   - 没有基线（`unknown`）→ 先在终端跑 `guard --bootstrap`（插件不提供这条，避免误盖章）。

## 2. 标准顺序

| 步 | 工具 | 说明 |
|---|---|---|
| ① 台词源 | `aicut_subs`（`apply` 才写盘） | 有内嵌 ASS/SRT 就不跑 ASR；无字幕才走 `asr_local` |
| ② 因果+选窗 | `aicut_plan` | 生成 `json/cutplan.json`；**已定型工程不要跑**，会覆盖 |
| ③ 粗剪 | 工程目录的 `cut.py` | 仓库外脚本，插件不代跑；跑完它会把帧网格时间回写 cutplan |
| ④ 写作表 | `aicut_narrate export=true` | 产出 `window_table.md`，用它逐窗对着画面写句子稿 |
| ⑤ 落盘 | `aicut_narrate sentences=<稿>` | 写盘前校验 `src` 绑定与钩子断言，不过直接退出 5 |
| ⑥ 体检 | `aicut_check` | 覆盖率、超槽、TTS 一致性；不通过先改稿 |
| ⑦ 出片 | `aicut_render` | TTS + 弹性适配 + 混音 + 合片 + 12 项验收 |
| ⑧ 质检 | `aicut_qc plan → 读图判定 → merge` | 宫格图路径由工具返回，用 `read_image` 逐格看 |
| ⑨ 归档 | `aicut_runs action=snapshot` | 记录产物指纹、句子稿、质检状态 |
| ⑩ 回收 | `aicut_clean`（先不带 `apply` 看清单） | 移入 `.trash` 可恢复，`empty` 才真删 |

## 3. 硬约束（违反就会出错，已知事故都出在这里）

1. **每句必须绑定源片区间**：句子稿每项带 `src:[起,止]`，必须**逐字等于**它绑定窗口的
   `src_start/src_end`。不等 → 退出码 5、不写任何产物。
2. **一句一窗**：`narration.items[i].t0` 必须等于该句窗口的 `new_start`。
3. **重切之后必须重跑旁白**：`cut.py` 吸附帧网格会让时间整体漂 ~0.04s；只重切不重写稿，
   全片音画错位。
4. **钩子 = 源片连续、未裁切的一整段爽点**，由 `project.json` 的 `recap.hook_clip` 锁定。
   钩子镜头不进 `used`，正片原样再演；钩子块要单独写 ≥2 句前置文案。
5. **原声留白窗**（`tier=hold_hl` / `ost_mode=original`）不写旁白、不算未覆盖；
   不要往留白块里塞句子。
6. **字数预算**：字数 ÷ 槽长 < 4.95 字/秒（默认配方 11 字一句、1.32s 一刀）。
7. **末段约 10s 原声留白**；正文稿内非钩子窗口的 `src_start` 不逆序。
8. **不要用「文件存在」当缓存**：产物是否最新只看内容指纹（`json/render_state.json`、
   `latest.json`），`aicut_status` 的门禁就是干这个的。
9. **数字必须有台词依据**：旁白出现具体数值（等级/金额/次数）时，必须能在该句覆盖窗口的
   台词里找到；画面浮字（`+5154`、`残り3033`）在 320px 抽帧下不可靠，不能当唯一依据。
   不确定就不写数字，改成「数值直接翻了几十倍」这类模糊表述。
10. **画面浮字是过程数据，剧情以台词为准**：同一集里可能同时存在「强化增量 +2750」
    「剩余点数 3033」「剩余 30%」等多套口径。旁白要用画面数字时必须说清口径
   （「又涨了两千多」而不是「一共三千」），也不要拿画面数字去质疑台词。
   `aicut check --ocr` 给的是「画面当时写了什么」的参考，不是对错判定。
11. **覆盖率不是目标**：原声留白是设计（爽点让原声自己演），不要为了覆盖率去填留白窗。
12. **只改旁白就用 `aicut_refit`，不要 `aicut_render`**：refit 会自动比对改了哪几句、
    只重合成它们、补 `tts` 盖章、再混音合片；`render` 会重切画面并把整集重跑一遍。
    前提是句子稿带 `src`——历史稿先用 `aicut_upgrade_sents` 升级。
13. **质检默认「未判 = 通过」**：`merge` 对没有 verdict 的句子按 `match=1, judged=false` 处理，
    所以必须让 `judged` 等于总句数才算真检过。失配句先 `aicut_qc probe` 三帧复核再改判，
    单帧在空镜/转场上假阳性率实测约 9%。

## 4. 写稿方式（会话内导演模式）

- 打开 `window_table.md`，按**源片剧情顺序**挑连续段（每段约 14s），段内按时间序切
  1.2–3.5s 窗口，画面不回跳。
- 每段对着该段画面与台词写 2–3 句，句子内容必须就是它覆盖的那几个窗口里正在发生的事。
- 钩子段单独写 3 句前置钩子文案。
- 自检：覆盖 `N/N`、`qc_report` 超槽 0、非钩子窗口 `src_start` 不逆序。

## 5. 质检闭环

1. `aicut_qc plan=<每批句数>`：返回 `grid_XX.jpg` 路径。
2. 用 `read_image` 逐格看，判定写到 `.qcframes/session/verdict_XX.json`：
   `{"i":3,"match":0,"why":"画面是 X，文案写的是 Y"}`。
3. `aicut_qc merge`：产出 `qc_visual.json` / `qc_rewrite.json`。
4. 失配句先 `aicut_qc probe` 抽 3 帧复核，排除单帧假阳性。
5. 改词后用 **`aicut_refit`**（见硬约束 12）：只重合成改动句、盖章、再混音合片，
   并核对 mp3 是否真的被重写，防「新词 / 旧音频」；它会顺带校验契约与门禁。

## 6. 失败排查

| 退出码 | 含义 | 下一步 |
|---|---|---|
| 2 | 参数 / 路径 / 解释器 | `aicut_env`、`aicut_status` 核对 |
| 4 | 渲染门禁阻断 | 产物与输入不一致，补跑上游；`allow_stale` 只用于调试 |
| 5 | 句子稿契约不过 | 检查 `src` 是否等于绑定窗口的源区间 |
| 6 | 前置完整性校验失败 | 缺产物或 `hook_clip` 未定义，补跑被跳过的阶段 |

## 7. 把识图派给 WorkBuddy（省上下文的关键）

DeepSeek 只做「派任务 → 收 JSON → 仲裁 → 落盘」，**不要自己逐张读图**。

1. **验收通道**：`workbuddy_doctor` 通过；`workbuddy_models` 选 `supportsImages: true` 的模型。
   **选型实测**（同一批 6 镜盲测）：
   | 模型 | credits | 人物/物件准确度 | 建议用途 |
   |---|---|---|---|
   | `deepseek-v4.1-flash` | 0.11 | 高（两人对坐、秃顶绿领带、白发老者都对） | **镜头描述、需要认人的任务** |
   | `hy4flash-free` | 0.00 | 一般（把白发老人说成“戴帽大胡子”、两人说成一人） | 质检宫格这类粗判定 |
   默认用 `deepseek-v4.1-flash`——一集 54 格质检也才 0.1 credits 量级。

   **两模型交叉验证实测**（同一集 54 格）：单帧原始判定里，免费模型误报 4 句（句2/4/47 等，
   把钩子复用段和空镜判成不符），`v4.1-flash` 误报 3 句（句17/20/27，抽到空街/黑帧）。
   两者对「真失配」都只锁定句11；probe 3 帧复核后完全一致。
   → **模型只影响误报多少，probe 仍是必做步骤。**
2. **起会话**：`workbuddy_session_start`，`cwd` = 工程目录，`permissionMode: plan`（只读），
   第一条 prompt 把判定规则、格子顺序、输出 JSON 格式一次讲清。
3. **批量**：`workbuddy_session_send` 复用同一会话。**只给图片路径 + plan 文件路径**，
   让它自己读句子文本，别把 54 句贴进 prompt。
4. **批次大小**：质检 6 句/张宫格可一次给 4 张；**镜头描述 6–10 镜/批**（20 镜曾 5 分钟无响应）。
   并要求「不要用 bash，直接用文件读取工具打开指定文件名」——plan 模式下 bash 会触发权限闸。
5. **probe 必做**：单帧判定在空镜/转场上假阳性约 13%。它的 0 分句子先跑
   `aicut_qc probe`，把 `probe_miss.jpg`（一行一句 × 3 帧）再发它复核，「3 帧有 1 帧支持就改 1」。
6. **仲裁权在你**：分歧按「台词 > 画面」定案（例：句4 画面只抽到酒杯特写，但该窗台词是
   「追放ってのは いいことずくめだぜ」→ 判支持）。
7. **落盘**：它不能写文件（plan 模式），verdict/描述由你写。
8. **交叉验证（可选，推荐做一次）**：模型 A/B 各跑一遍，verdict 分别存
   `.qcframes/session/cross/<模型名>/`，然后
   `aicut_qc_compare(a_dir, b_dir, project)` → 一致率 + 分歧 + **probe 并集**；
   只对并集跑 `aicut_qc probe`。实测两模型一致率 94.4%（51/54），分歧全是单帧抽样噪声。

镜头描述可外包，但**仍要抽检人物/物件**：免费模型实测 6 镜里 2–3 镜有偏差，
`deepseek-v4.1-flash` 明显更准（6 镜里只有 1 镜与我旧描述互补而非冲突）。只信 `desc` 的动作与场景、
`depth` 的情绪；人名与物件抽 1–2 镜核对；**不要整表覆盖 `shots_desc.json`**。

## 8. 不要做的事

- 不要在 web 校对台（`/flow` 页）点「运行」按钮：旧 17 步链会覆盖已定型的 cut-first 数据。
  审稿只用逐句台的句级锚点 + 确认。
- 不要把「按剧情顺序写好的 N 句」按窗口序号均匀分配。
- 不要在 `cutplan.json` 改了 `src_start/src_end` 后只重跑混音——画面变了必须
  `cut.py → narrate_cut --sentences → r6 → r7`。
- 不要手改 `config/tts_calibration.json`（那是 `recalibrate()` 的产物）。
